# astrbot_plugin_horserace

将 [shinianj/nonebot_plugin_horserace](https://github.com/shinianj/nonebot_plugin_horserace) 移植为 AstrBot 插件，保留赛马引擎、9 个事件包（103 条顶层事件）与自定义 JSON 事件格式。

适用于 AstrBot >=4.16,<5、Python >=3.10 的群聊。使用平台无关的群组、用户和消息接口；未对所有平台进行实机验证。不依赖 NoneBot、OneBot SDK 或 nonebot_plugin_imageutils。

## 安装

解压后将 `astrbot_plugin_horserace` 目录放入 AstrBot 的 `data/plugins/`，确保 `main.py`、`metadata.yaml` 直接位于该目录下。通过 AstrBot 管理面板重启/重载插件。

项目仓库：https://github.com/Cvandia/astrbot_plugin_horserace 。通过 AstrBot 管理面板使用此仓库地址安装，或按下文手动安装。

## 指令

以下省略 AstrBot 中配置的唤醒前缀。例如前缀为 `/` 时发送 `/赛马创建`。马名与指令之间必须有空格。

| 指令 | 用途 | 权限 |
| --- | --- | --- |
| 赛马帮助 | 显示帮助 | 所有人 |
| 赛马创建 | 在当前群创建比赛 | 群成员 |
| 赛马加入 闪电 | 报名；马名支持空格，最长 24 字符 | 群成员 |
| 赛马开始 | 开始或继续比赛 | 创建者 / AstrBot 管理员 |
| 赛马状态 | 查看报名与回合状态 | 群成员 |
| 赛马重置 | 创建/最近开赛满配置时间后释放比赛 | 群成员 |
| 赛马暂停 | 暂停，保留回合、马匹和状态 | AstrBot 管理员 |
| 赛马清空 | 立即取消本群比赛 | AstrBot 管理员 |
| 赛马事件重载 | 重载内置与自定义事件 | AstrBot 管理员 |

例如：甲发送 `赛马创建`，甲发送 `赛马加入 闪电`，乙发送 `赛马加入 赤兔`，甲发送 `赛马开始`。每人限报名一次，同一平台实例的同一群共享比赛，即使 AstrBot 启用了群内分用户会话。

管理员指 AstrBot 配置的管理员，群主/群管理身份不自动授予这些权限。普通群成员无法提前强制清空比赛。超时重置允许释放运行中的比赛，与原版超时语义一致。

## 配置

代码按职责拆分：`main.py` 仅负责插件生命周期和指令注册；`service.py` 管理房间、指令行为与后台任务；`settings.py` 校验配置；`event_loader.py` 加载事件；`race_group.py`、`horse.py`、`events_main.py` 和 `start.py` 保留并修复上游比赛引擎。

在管理面板修改插件配置；新比赛使用新规则，进行中的比赛保留创建时规则。

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| setting_track_length | 20 | 跑道长度，5~100 |
| setting_random_min_length / setting_random_max_length | 0 / 15 | 随机传送位置范围，不得超出跑道 |
| base_move_min / base_move_max | 1 / 3 | 基础移动范围，1~20 |
| min_player / max_player | 2 / 8 | 最少/最多玩家，2~16 |
| setting_over_time | 120 | 允许重置的等待秒数，10~3600；创建/每次开赛或继续时计时 |
| event_rate | 450 | 随机事件概率（千分比），0 禁用普通随机事件 |
| round_interval | 6.0 | 回合播报后的等待秒数，1~60 |
| max_rounds | 100 | 回合上限，1~500；达到上限仍无胜者则平局 |
| image_mode | false | 使用 AstrBot 内置文字转图片；失败自动回退文字 |

默认文字播报无需渲染服务；图片模式依赖 AstrBot 的文字转图片服务及其字体/网络配置，不保证所有 emoji 均可显示。可先用文字模式确认运行。

## 自定义事件

将 UTF-8 JSON 文件放入 `data/plugin_data/astrbot_plugin_horserace/events/`，再发送 `赛马事件重载`。此目录独立于插件源码，便于保留自定义内容。自定义事件会追加到内置事件，而不是替换同名内置文件。

```json
[
  {
    "event_name": "顺风",
    "describe": "<0>遇到顺风，额外前进两格！",
    "target": 0,
    "move": 2
  }
]
```

详见 `事件详细模板.txt`；原说明中的 `setting.py` 对应本版管理面板配置。延迟事件参数必须至少 2 回合；事件嵌套最多 20 层、单文件最多 2MB。错误事件包整包跳过并记录原因，其他包正常加载；无可用事件时保留旧列表。重载不会重复累计事件，运行中的任务使用当前快照，继续或新比赛使用新列表。

## 移植改动与边界

- 改为 AstrBot Star 插件、生命周期和权限装饰器；异步回合任务，不阻塞其他群或指令。
- 暂停、清空、重置及卸载时取消任务，异常自动释放当前房间，防止旧任务误删新比赛。
- 报名阶段从创建或最近一次成功加入起计时，连续 60 秒无人加入自动清场并通知群聊；开赛即取消报名计时，暂停比赛不触发此清场规则。
- 修复上游延迟事件字段遗漏、替换马匹引用未定义变量、重复重载累加、一次性随机事件重复抽样，以及 buff 按名称删除的问题。
- 空事件列表/零概率正常运行；死亡或离场马匹不列为胜者；每场最多 32 匹马（包括事件生成的马），避免持续召唤无限膨胀。
- 保留上游“新状态通常下一回合生效”的规则；同回合到达终点者并列获胜。
- 比赛仅保存在内存，重载插件/重启会结束所有比赛；无积分、下注或金币系统。
- 事件文字原样保留，包含网络梗、粗俗或不适合部分群聊的内容；部署者可按群需求编辑内置 JSON。

## 验证

```bash
python -m unittest discover -s tests -v
```

测试覆盖真实引擎、全部事件包、特定事件回归、批量比赛，以及使用 AstrBot API 替身的任务生命周期与群隔离。替身测试不能证明已在真实 AstrBot/QQ/Telegram 上运行；本交付未连接运行实例。建议部署后用两个群成员按上述流程验收一次，再检查管理员暂停/继续和事件重载。

本次移植已通过 39 项测试，含 200 个随机种子的整场比赛模拟；103 条事件还分别在 5 个随机种子下执行验证。测试不需要安装 AstrBot，使用的 API 替身仅用于隔离传输层。
