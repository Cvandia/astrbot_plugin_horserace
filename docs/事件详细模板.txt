==========完整示例：遗迹探险（可直接使用）==========

一、保存与加载

只复制下面代码块内从 [ 到 ] 的 JSON 内容，保存为 UTF-8 编码的“遗迹探险示例.json”。
将文件放入 data/plugin_data/astrbot_plugin_horserace/events/，由 AstrBot 管理员发送“赛马事件重载”。
加载成功后，本例会加入随机事件池；文件名不是聊天指令，不会每回合必定触发。
JSON 不支持 # 或 // 注释，因此字段备注放在代码块后面，不要一起复制进 .json 文件。

```json
[
  {
    "event_name": "示例：遗迹探险",
    "describe": "<0>进入一座遗迹，打开了神秘宝箱！\n",
    "target": 0,
    "race_only": "example_minecraft_ruins_v1",
    "random_event_once": [
      [
        69,
        {
          "event_name": "示例：宝箱奖励",
          "describe": "<0>找到末影珍珠，额外前进3格，并获得两回合轻盈效果！\n",
          "target": 0,
          "move": 3,
          "rounds": 2,
          "name": "遗迹轻盈",
          "move_min": 1,
          "move_max": 1,
          "delay_event_self": [
            2,
            {
              "event_name": "示例：遗迹回响",
              "describe": "<0>听到遗迹的回响，又额外前进2格！",
              "target": 0,
              "move": 2
            }
          ]
        }
      ],
      [
        99,
        {
          "event_name": "示例：踩中陷阱",
          "describe": "<0>踩中了遗迹陷阱，下一回合停止前进！",
          "target": 0,
          "rounds": 1,
          "name": "遗迹陷阱",
          "locate_lock": 1
        }
      ]
    ]
  }
]
```

二、字段备注

1. 最外层 [ ... ] 是事件包数组。一个文件可以放多条顶层事件，事件之间用英文逗号分隔。
   本例只有一条顶层事件；“宝箱奖励”“踩中陷阱”“遗迹回响”都是它的子事件，不会独立进入随机池。

2. event_name 是日志中显示的事件名称，describe 是发送给群聊的描述。
   <0> 会替换成事件发起马匹的显示名称；本例 target 为 0，所以所有效果都作用于发起马匹自己。
   \n 表示消息换行，方便把外层描述和随机分支描述分开。

3. race_only 是“本场唯一标识”，全场共享，不是每位玩家各有一次。
   本例在同一场比赛中最多触发一次。若多个顶层事件用了相同标识，它们共用一次机会。
   希望允许本场反复触发时，删除这一行；写其他独立事件时请使用不同标识。

4. random_event_once 在本事件触发时抽取一次分支。
   本例抽取的整数范围是 0~99，两端都包含：
   - 0~69 共 70 个整数，执行宝箱奖励，概率为 70%。
   - 70~99 共 30 个整数，执行踩中陷阱，概率为 30%。
   阈值是累计上界，不是两个独立权重；写成 70 和 100 并不等于严格的 70%/30%。
   这两个百分比是“本事件已经触发之后”的分支概率；本事件是否触发还受 event_rate 和事件池数量影响。

5. move: 3 表示触发当回合额外前进 3 格，正常基础移动仍另外计算。
   到达跑道终点会按跑道长度截断，不会越过终点；若比赛已经结束，后续回响也不会再执行。

6. rounds: 2、name: "遗迹轻盈"、move_min: 1、move_max: 1 合起来定义一个持续状态。
   该状态从下一回合开始，持续两回合，每回合额外获得 1 格移动力。
   这里的 1 是加成，不是把基础移动速度设置为 1；当前字段名是 rounds。

7. delay_event_self: [2, {...}] 表示两回合后，以当前事件发起马匹为发起人执行回响子事件。
   子事件也需要自己的 target；这里 target: 0 仍表示作用于这匹马自己。
   延迟值必须是至少 2 的整数，不能照抄上方旧格式示意中的 [1, {事件}]。

8. 失败分支中的 rounds: 1 与 locate_lock: 1 表示下一回合停止基础移动一次。
   它不会取消触发当回合的正常移动；其他事件额外提供的位移仍按引擎规则结算。
   如果这匹马已有不死图腾保护，陷阱的负面效果会被抵挡；奖励分支照常生效。

三、回合结算举例

假设本事件在第 R 回合触发，比赛仍在继续，并且没有其他事件干扰：
- 获得奖励时：第 R 回合额外前进 3 格；第 R+1 回合有 1 格轻盈加成；第 R+2 回合有 1 格轻盈加成，并额外前进 2 格回响位移；第 R+3 回合轻盈结束。
- 踩中陷阱时：第 R 回合仍可正常移动；第 R+1 回合基础移动为 0；第 R+2 回合恢复正常。

四、扩展字段与离场时序提醒

- 如需奖励不死图腾，可另写一个 target: 0、negative_immunity: 1 的事件；此字段需要 v1.1.0 或以上版本。
- away: 1 始终在下一回合生效，离开函数保持原有逻辑，不受 immediate 影响。
- die: 1 默认也是下一回合生效；只有同时设置 immediate: 1 时，死亡状态才在触发当回合生效。
- 纯描述子事件也应保留 target: 0；不要只复制上方旧示意里的 rate 和 describe，否则无法通过当前事件校验。
