# 赛马游戏工作台

## 打开页面

安装或更新插件后，在支持插件 Pages 的 AstrBot 管理面板中打开本插件的「赛马游戏」页面。页面使用 AstrBot 注入的 Bridge 和管理员会话，不需要填写 API 密钥。

`metadata.yaml` 声明了 `pages: [{name: dashboard, title: 赛马游戏}]`。按项目要求，编辑源文件放在 `page/dashboard/`；AstrBot 实际扫描 `pages/dashboard/`，因此仓库同时提交生成的运行副本。修改源码后运行：

```bash
python tools/build_dashboard.py
```

当前 AstrBot 的侧边栏和页面标题通过 `.astrbot-plugin/i18n/zh-CN.json` 中的 `pages.dashboard.title` 显示为「赛马游戏」，`_page.json` 引用同一语言键。只填写元数据标题会回退为目录名 `dashboard`；更新语言文件后需重载插件并刷新管理面板。

旧管理面板可能没有 Pages 支持。升级 AstrBot 后重载插件；若仍没有入口，检查该版本的插件页面支持。独立打开 `page/dashboard/index.html` 只提供离线编辑、结构检查和导入导出，保存与试跑需要 AstrBot 后端。

## 编写事件包

1. 新建事件，或在顶部选择已有事件包。原事件会转换为积木，内置包载入后是可编辑副本。
2. 点击黄色事件积木中的名称、消息和目标设置基础信息；消息可换行，Shift+Enter 插入换行，Enter 确认。
3. 从工具箱把效果拖到事件内部。位移、buff、条件、死亡/离场和随机/延迟分别分类；也可以用「快速添加」。嵌套时先选中对应容器，再添加结果、子事件或附加 buff。
4. buff 条件、移除和附加 buff 都是下拉选项，空选表示不限制或不添加。选项来自内置 buff、当前草稿及机器人事件包。移除还可选择已有 buff 显示名；在 buff 下拉框中，图腾保护只出现在条件选项内，普通移除对它无效。新增自定义 buff 标识可通过高级 JSON 的 `other_buff` 引入，之后会出现在选项中。
5. 持续 buff 设置回合数及效果，从下一回合生效。随机容器内放多个「随机结果」，每个结果连接一个子事件，权重使用正整数；延迟和连锁容器也连接一个子事件。
6. 点击「校验事件包」，再导出或保存。游离积木、重复设置同一字段、缺少子事件等情况会提示并阻止保存；已有同名自定义包需要确认覆盖，成功后自动重载。

原引擎的事件格式表示一组效果，积木上下顺序用于组织界面，实际结算顺序仍由引擎决定；同一事件的同一种效果只放一次。多个移除 buff 或附加 buff 积木可以叠放。灰色「高级字段（保留）」积木保存暂未提供专用积木的旧字段，删除它会删除对应字段。

高级 JSON 默认收起，支持完整格式；编辑后点击「应用 JSON 到积木」。日常编写无需手写 JSON。撤销、重做和整理视图用于调整画布。

浏览器保存事件和当前积木草稿，未连接完整的积木也可在刷新后继续编辑。关闭或刷新前，请应用高级 JSON 修改并导出重要内容；浏览器草稿不代替文件备份。每包允许 1~128 条顶层事件，最大 128KB，每个事件最多 1000 个积木。完整字段及示例见 [事件详细模板](事件详细模板.txt)。

保存目录为 `StarTools.get_data_dir("astrbot_plugin_horserace") / "events"`。文件名允许中英文、数字、下划线和短横线，扩展名为 `.json`。页面不支持写入其他目录或改写内置包。写入采用临时文件替换，重载失败时恢复旧文件；进行中的比赛继续使用原事件快照。

## 开发测试

- 「仅触发选中事件一次」：第一回合由指定马匹触发选中事件，后续仍结算持续和延迟效果；普通随机事件关闭。
- 「整个事件包随机比赛」：按设置概率触发当前草稿内的事件，使用真实引擎完成比赛结算。
- 支持 2~8 匹初始马匹，每行填写 `马名|初始位置`，可为发起者携带本场负面效果免疫。
- 支持种子、跑道长度、回合上限和事件概率设置。相同输入可复现结果；测试使用独立随机数发生器，不消耗群内比赛的全局随机状态。
- 上一回合、下一回合、播放和滑块用于查看位置、状态及日志；可导出完整回放 JSON。

测试使用独立比赛对象，不创建聊天场地或发送群消息。死亡时机、下一回合离场、图腾免疫、交换和停滞均复用原引擎。测试范围为 1~100 回合、跑道 15~100 格（兼容默认随机传送范围），单次最多结算 5000 次事件，超过时明确停止。

这是事件逻辑测试，不验证平台消息发送、图片服务和实际群聊权限。

## 接口与本地验证

四个接口通过 AstrBot 的插件扩展 API 注册，由管理面板的认证代理访问：

| 方法 | 插件内路径 | 用途 |
| --- | --- | --- |
| GET | `dashboard/packs` | 读取内置及自定义事件包 |
| POST | `dashboard/validate` | 校验 `pack` |
| POST | `dashboard/simulate` | 运行独立模拟 |
| POST | `dashboard/save` | 保存 `filename`、`pack`，覆盖需 `overwrite: true` |

生产接口只使用 `window.AstrBotPluginPage`，静态资源使用相对路径。Blockly 13.4.0 及官方多行输入组件在 `vendor/blockly/` 内本地分发，不使用 CDN；仅生成事件 JSON，不生成或执行用户程序。相关许可见 [第三方组件](../THIRD_PARTY_NOTICES.md)。后端兼容新版 `astrbot.api.web` 和旧版 Quart 请求适配器。

```bash
python tools/build_dashboard.py
node --check page/dashboard/app.js
node --test tests/test_block_editor.cjs
python -m unittest discover -s tests -v
```

积木测试使用 Node.js >=22，无需额外安装 npm 依赖；测试加载实际分发的 Blockly 和多行字段，验证全部内置事件的导入导出与积木修改结果。

自动测试覆盖页面副本一致性、输入边界、真实引擎时机、种子隔离、事件链预算、接口响应、目录限制、覆盖确认以及失败回滚。页面已使用本地独立 HTTP 测试环境检查表单同步、校验、保存和回放；仍需在用户实际 AstrBot Pages 宿主中检查入口发现与认证代理联调。
